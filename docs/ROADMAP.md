# 开发计划

更新日期：2026-10-03。以下为待实施计划，具体完成状态统一记录于 [开发进展](DEVELOPMENT.md)。

优先级：正常生成稳定性 → 捕获准确性 → Token 准确性 → 性能与 UI → 高级分析。时间安排以每阶段验收结果决定。

## P0：完成 V1 准确性验证

| 工作 | 实施方向 | 完成标准 |
|---|---|---|
| 捕获点核对 | 构造多个事件监听器、宏、EJS、世界书、工具及扩展注入组合，对比事件快照与实际发往 ST 的消息；先评估官方事件，证据显示缺口后再评估透明拦截 | 捕获边界清楚；正常/流式/取消/异常生成均不被分析阻塞或修改 |
| Token 语义校准 | 对照 ST 整体计量和 provider 返回 usage，确认逐条 padding、模型映射、内部估算和请求级开销；明确区分分词、估算与未计量部分 | 总量与分项关系可解释，回退状态不冒充精确计量 |
| 超长上下文验收 | 在隔离 ST 中构造 100K–200K token 可计量上下文，测捕获、tokenizer 请求数、内存、折叠列表、Raw 与导出 | 有实际 token 与时间数据；生成流畅，页面保持响应；必要优化由瓶颈证据驱动 |
| 扩展兼容回归 | 验证禁用/重新启用、刷新、并行生成、新捕获覆盖旧任务、常用注入扩展与当前 ST 版本 | 无重复监听和旧任务覆盖新结果，记录经过实测的兼容组合 |

## P1：V1 易用性与维护

- 完善快照 schema 校验、格式版本、损坏数据处理与配额反馈。验收：损坏或不完整 localStorage 数据不让 Final Context 页面崩溃。
- 为 Raw 序列化和重复内容计量增加有界缓存，并改善超长内容渲染。验收：切换视图不重复计量；缓存有明确容量边界。
- 使用既有不变消息作为位置锚点改善大量插入/删除后的修改匹配。验收：重复内容、位置漂移和工具消息 fixture 可解释且不引入长文本编辑距离。
- 补可自动运行的浏览器 smoke、最低 Node 版本说明与 CI。验收：新环境按文档可复现自动检查，测试数据保持隔离。
- 核对手机端、键盘操作、复制失败与下载反馈。验收：窄屏下摘要和差异可读，操作反馈明确。
- 整理上游历史文档与当前功能的对应关系，更新兼容版本记录和变更日志。

## V2：来源与构建阶段分析

| 能力 | 建议切入点 | 开工前要证明 |
|---|---|---|
| Source Map / provenance | 在 Prompt Builder/prepareOpenAIMessages 阶段保留稳定条目标识、来源与合并关系 | 宿主有可观察的构建阶段元数据；不能把文本相似度作为精确来源 |
| Character / World Info / Persona 分项 | 复用 provenance 记录汇总 | 分项合并、重复内容和裁剪的归属可解释 |
| Dry Run | 核对宿主已有 dryRun 构建路径及其扩展事件行为 | 与正常渲染结果等价，可避免发送、聊天写入和扩展副作用；保留观察模式 |
| Provider context window | 使用可信模型元数据来源或明确的用户配置 | 来源、更新时间与未知模型处理明确 |
| Prompt cache 分析 | provider usage/cache 字段及稳定前缀比较 | provider 差异与不可得信息不会被猜测填充 |
| 宏展开检查 / Before vs After | 构建阶段的前后文本与条目标识 | 具备真实阶段数据，而非反向猜测 |
| 预设优化建议 | 基于已经验证的 token、diff 与 provenance 数据 | 建议附可核对证据，修改仍由用户决定 |

V2 需要单独确定首个功能范围和验收样例，按最小可验证能力推进。
